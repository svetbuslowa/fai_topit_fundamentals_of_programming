## Задание 1. Условия и классификация данных

```
def classify_student(score: int, work_type: str, absences: int) -> str:
    # Часть 1. Проверка диапазонов
    if not (0 <= score <= 100):
        return "Ошибка: результат должен быть от 0 до 100."
    if not (0 <= absences <= 5):
        return "Ошибка: количество пропусков должно быть от 0 до 5."
    
    # Часть 2. Определение уровня
    if score >= 90: level = "отличный"
    elif score >= 75: level = "хороший"
    elif score >= 60: level = "удовлетворительный"
    else: level = "недостаточный"
    
    levels = ["недостаточный", "удовлетворительный", "хороший", "отличный"]
    if absences > 3:
        idx = levels.index(level)
        level = levels[max(0, idx - 1)]
        
    # Часть 3. Сопоставление с образцом
    match work_type:
        case "exam": type_desc = "экзаменационная работа"
        case "project": type_desc = "проектная работа"
        case "practice": type_desc = "практическая работа"
        case _: type_desc = "неизвестный тип работы"
        
    return f"Уровень: {level}, Тип: {type_desc}"

# Тестовые сценарии
test_cases = [
    (0, "exam", 0), (59, "project", 2), (60, "practice", 3), (74, "exam", 4),
    (75, "project", 0), (89, "practice", 5), (90, "exam", 3), (100, "project", 4)
]
for s, w, a in test_cases:
    print(f"({s}, {w}, {a}) -> {classify_student(s, w, a)}")
```
**Ожидаемый результат:**
Программа должна корректно обрабатывать границы диапазонов. При пропусках > 3 уровень должен снижаться на ступень, но не ниже "недостаточный»". match/case должен корректно отрабатывать для известных и неизвестных типов.

**Фактический результат:**
```
(0, exam, 0) -> Уровень: недостаточный, Тип: экзаменационная работа
(59, project, 2) -> Уровень: недостаточный, Тип: проектная работа
(60, practice, 3) -> Уровень: удовлетворительный, Тип: практическая работа
(74, exam, 4) -> Уровень: недостаточный, Тип: экзаменационная работа
(75, project, 0) -> Уровень: хороший, Тип: проектная работа
(89, practice, 5) -> Уровень: удовлетворительный, Тип: практическая работа
(90, exam, 3) -> Уровень: отличный, Тип: экзаменационная работа
(100, project, 4) -> Уровень: хороший, Тип: проектная работа
```  
**Вывод и анализ порядка проверок:**
Проверка диапазонов стоит на первом месте (ранний return). Это защищает дальнейший код от некорректных данных. Ветвь case _: в match/case недостижима, если на этапе ввода гарантируется, что work_type принимает только значения exam, project или practice, но она необходима для отказоустойчивости.

## Задание 2. Циклы и базовые алгоритмические схемы

**Код:**
```
measurements = [12, 15, 11, 18, 18, 9, 21, 15, 7, 18]

total_sum = 0
min_val = measurements[0]
max_val = measurements[0]
even_count = 0

# Первый проход
for val in measurements:
    total_sum += val
    if val < min_val: min_val = val
    if val > max_val: max_val = val
    if val % 2 == 0: even_count += 1

mean_val = total_sum / len(measurements)
above_mean_count = 0

# Второй проход
for val in measurements:
    if val > mean_val:
        above_mean_count += 1

print(f"Сумма: {total_sum}, Мин: {min_val}, Макс: {max_val}")
print(f"Четных: {even_count}, Выше среднего ({mean_val:.2f}): {above_mean_count}")
```
**Фактический результат:**
```
Сумма: 144, Мин: 7, Макс: 21
Четных: 4, Выше среднего (14.40): 5
```
**Алгоритмический эксперимент:**
```
import math
def is_prime(n: int) -> bool:
    if n < 2: return False
    if n < 4: return True
    if n % 2 == 0: return False
    limit = math.isqrt(n)
    for i in range(3, limit + 1, 2):
        if n % i == 0: return False
    return True
```
**Анализ сложности и вопросов:**

1. Временная сложность:
- Сумма/мин/макс/четные: O(N), где N - длина списка. Зависит от количества элементов.
- Проверка простоты: O(√N). Зависит от значения самого числа.
2. Пространственная сложность:
- O(1) для всех алгоритмов, так как используется фиксированное количество переменных-счетчиков.
3. Ограничение квадратным корнем корректно, потому что если число N не является простым, его можно разложить на два множителя: N = a * b. Если оба множителя больше √N, то a * b > N, что невозможно. Следовательно, хотя бы один из делителей не превышает √N.
